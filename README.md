# Календарь конкурсов

Статическая страница: календарь сроков подачи заявок и дат конкурсов учебных
заведений, список заведений, карточка события, страница заведения.

Данных в репозитории нет. Пользователь сам открывает файл базы `muzcatalog.db`
(SQLite) на первом экране — файл читается прямо в браузере и никуда не отправляется.

```
index.html    экран импорта и рабочий экран
app.js        чтение базы, фильтры, отрисовка
styles.css    оформление: светлая и тёмная тема, печать
.nojekyll     чтобы Pages не обрабатывал файлы Jekyll
```

Зависимость одна — [sql.js](https://sql.js.org) с CDN (читает SQLite в браузере),
плюс шрифты Golos Text и IBM Plex Mono. Сборки нет, устанавливать нечего.

## Публикация на GitHub Pages

Эта папка — готовый сайт: кладётся в репозиторий как есть, в корень.

```
cd renderer
git init -b main
git add .
git commit -m "Календарь конкурсов"
git remote add origin git@github.com:<логин>/<репозиторий>.git
git push -u origin main
```

Затем **Settings → Pages → Source: Deploy from a branch → main / (root)**.
Через минуту сайт открывается по адресу `https://<логин>.github.io/<репозиторий>/`.
Workflow не нужен: публикуется статика как есть.

Файл `muzcatalog.db` в папке (если он есть) — локальная копия для просмотра на
своей машине. В репозиторий он не попадает: его исключает `.gitignore`.

## Как пользоваться

1. Открыть сайт — появляется экран импорта.
2. Перетащить `muzcatalog.db` или выбрать файл. Поддерживается и JSON того же вида.
3. Дальше работает календарь; разобранные данные остаются в `localStorage` этого
   браузера, поэтому при следующем заходе есть кнопка «Открыть прошлую базу».

Если база раздаётся откуда-то ещё, её адрес можно передать параметром — тогда
импорт пропускается:

```
https://<логин>.github.io/<репозиторий>/?db=https://example.org/muzcatalog.db
```

Чужой домен должен отдавать файл с заголовком CORS.

## Что умеет страница

- **Период**: 3, 6, 12 месяцев или всё время; стрелки листают на тот же шаг,
  «сегодня» возвращает к текущему месяцу. Фильтр влияет и на сетку, и на список,
  и на счётчики заведений.
- **Календарь**: красная полоска в дне — срок подачи заявок, синяя — проведение.
  Клик по дню показывает его события.
- **«Ближайшее»**: дата, сколько дней осталось, конкурс, заведение. Сроки ближе
  двух недель подсвечены.
- **Карточка события**: даты, номинации, награды, контакты оргкомитета, источник,
  кнопки «позвонить» и «написать».
- **Страница заведения**: контакты, сайт, раздел конкурсов, счётчики и все его
  конкурсы со сроками.
- **Фильтры** «только свои» и «только сроки заявок», поиск по названию и городу.
- **Тема**: системная по умолчанию, кнопка ◐ переключает, выбор запоминается.
- **Печать**: панели и кнопки уходят, календарь и список остаются.

## Формат базы

Страница ждёт две таблицы.

`places`: `kp_id, name, abbr, profile, city, address, phone, email, website, host,
crawl, competitions_page`

`contests`: `kp_id, name, level, own, annual, non_music, years, first_seen, last_seen,
deadline_text, deadline_date, event_text, event_date, nominations, prizes, contacts,
docs_count, doc_url, link, source, date_precision`

В календарь попадают строки с заполненными `deadline_date` или `event_date`
в формате `ГГГГ-ММ-ДД`. Словесные даты («16 октября 2026») разбирает сборщик базы,
не страница.

Вместо базы можно открыть JSON того же вида:

```json
{ "places": [ … ], "contests": [ … ] }
```

## Если что-то не так

| Признак | Причина |
|---|---|
| «не загрузился sql.js» | нет доступа к CDN; положите `sql-wasm.js` и `sql-wasm.wasm` рядом и поправьте пути в `index.html` и `app.js` |
| «в базе нет таблиц places и contests» | открыт не тот файл |
| календарь пустой | в базе нет строк с датами в `deadline_date` / `event_date` |
| при открытии с диска не работает `?db=` | браузер запрещает `fetch` по `file://` — поднимите локальный сервер: `python -m http.server 8000` |
